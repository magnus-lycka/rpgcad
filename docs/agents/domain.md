# Domain docs

This repository uses a single-context layout:

- GLOSSARY.md at the repository root.
- Architecture decision records in docs/adr/.

Before exploring the codebase, read the glossary and ADRs relevant
to the work. If absent, proceed silently. The domain-modeling
skill creates them as terms and decisions are resolved.

Use the glossary's vocabulary in code, tests, issues, and proposals.
Flag gaps for domain-modeling when appropriate.

Explicitly identify conflicts with existing ADRs and explain
the reason for proposing a change.
